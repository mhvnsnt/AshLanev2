# Round 6 — Characters & Rigs

**Rule (unchanged): only CC0 / public-domain / permissive (MIT/Apache-2.0/BSD/Unlicense/OFL) goes in the game build.** CC-BY allowed with written attribution. AGPL/GPL CODE never touches the shipped game — build-time tools stay quarantined in `tools/`. Exported model OUTPUTS carry the OUTPUT license, not the tool license — verify per tool. Licenses below were read from the actual license sources on 2026-10-06; re-verify before shipping.

## 1. MakeHuman (+ MPFB2)

- **URL:** https://www.makehumancommunity.org | MPFB2: https://github.com/makehumancommunity/mpfb2
- **What:** Parametric human-body generator. 15+ years old; sliders for height, weight, age, gender, ethnicity, muscularity; detailed face controls; built-in clothing + hair assets. Exports OBJ/FBX/DAE; MPFB2 brings the same pipeline inside Blender 4.x (direct mesh manipulation, any Blender export format including glTF).
- **License:** MakeHuman **source code = AGPL-3.0**. **Models exported via the file-export of an OFFICIAL, UNMODIFIED MakeHuman binary are released under a CC0 exception** (special exception by the copyright holders — option to take CC0 1.0 for characters exported that way). MPFB2: **addon code GPL-3, mesh + bundled assets CC0** (no GPL obligation on exported output). Community asset packs on makehumancommunity.org: check per pack (CC0 or CC-BY).
- **Verdict:** ✅ COMMERCIAL-SAFE — the primary recommended parametric human source. Use only official unmodified exports for CC0 coverage; keep the AGPL/GPL tool code itself out of the game (build-time only).
- **Notes:** Best path for diverse body types across a 30+ fighter roster (habitus variants: heavy, tall, muscular). Headless/batch generation possible via MPFB2 scripting. The repair lane (weight transfer to game skeleton) applies to these meshes like any other.

## 2. MB-Lab

- **URL:** https://github.com/animate1978/MB-Lab (archived) | community: https://mb-lab-community.github.io/MB-Lab.github.io/
- **What:** Parametric photorealistic-humanoid Blender add-on (formerly ManuelbastioniLAB). Three sliders drive 90%+ of a character (age 18–80, body mass, body tone), plus face/body detail tools, skin/eye shaders, poses, proxies. Last stable 1.8.0 (2024-03).
- **License:** **Python code GPL-3.0; all database parts (base blend library + JSON morph data) AGPL-3.0.** Manuel Bastioni stated explicitly (blenderartists, 2019) that "every model generated by MBLab is AGPL." Contested in community debate, but the license.txt in the repo ships AGPL for the bundled `mb_*` character data — the export-risk interpretation is unresolved.
- **Verdict:** ❌ PROTOTYPE-ONLY / license-trapped — archived project + AGPL-covered generated meshes make it a shipping liability. Use MakeHuman/MPFB2 instead for the same job.
- **Notes:** ⚠️ Cousin project **CharMorph** (Upliner, actively maintained, reimplements MB-Lab-style morphing without MB-Lab code) inherits the same trap: addon GPL-3, bundled `mb_*` character data **AGPL-3.0** — only its `antonia` (CC-BY-3.0) and `reom` (CC-BY) bases are ship-safe with attribution. Check each character's `license.txt` in CharMorph-db before exporting.

## 3. Rigify (Blender bundled)

- **URL:** https://docs.blender.org/manual/en/4.0/addons/rigging/rigify/index.html | ships inside Blender (`Edit > Preferences > Add-ons`)
- **What:** Auto-rig builder from building-block meta-rigs: human meta-rig + cat/wolf/horse/bird/shark, FK/IK limb chains, full face rig, fingers. Generates a control rig + deform bones (`DEF-` bones export to game engines); the manual explicitly says generated rigs distribute freely and function without Rigify installed.
- **License:** **GPL** (add-on; bundled with Blender). Standard Blender rule applies: what you CREATE with Blender (meshes, rigs, renders) is your sole property — the GPL covers the software, not artistic output. A rig exported to GLB carries no GPL code (the `rig_ui.py` helper is a Blender text-block that does not survive glTF export).
- **Verdict:** ✅ COMMERCIAL-SAFE as a build-time tool. Export DEF-bones-only to the game skeleton; never vendor Rigify Python into the shipped game.
- **Notes:** Rigify builds controls/bones only — it does NOT skin the mesh; weights still need transfer/paint (fits our weight-transfer repair lane). Candidate standard rig for all parametric humans (MakeHuman/MPFB outputs) so retargeting stays uniform.

## 4. mGear

- **URL:** https://github.com/mgear-dev/mgear (releases: https://github.com/mgear-dev/mgear_dist/releases)
- **What:** Rigging framework for Autodesk Maya — modular auto-rig builder (guides → full FK/IK control rig), C++ solvers, synoptic pickers, UE/Unity export helpers. Used in game/film production.
- **License:** **MIT** (stated in repo README).
- **Verdict:** ✅ COMMERCIAL-SAFE code, but ⚠️ Maya-gated — mGear runs inside Autodesk Maya (proprietary). Useful only if the pipeline includes a Maya seat; our Blender-first pipeline should prefer Rigify. Documented for completeness in case Maya enters the toolchain.
- **Notes:** Generated rigs (like Rigify's) are tool output — your property. If Maya is ever licensed, mGear's guide-based workflow is faster than hand-building control rigs.
