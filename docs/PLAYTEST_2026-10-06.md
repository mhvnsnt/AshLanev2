# AshLane Live Playtest — 2026-10-06

**Target:** https://mhvnsnt.github.io/AshLanev2/ (GitHub Pages, mobile viewport 390×844, touch)
**Method:** Headless Chromium + Playwright, real inputs (keyboard + button clicks), pixel-diff verification. Every claim below is tied to a screenshot in `docs/playtest/2026-10-06/`.

## Verdict

The game boots clean and the open-world roam mode genuinely works — but **every structured fight mode (Exhibition, Story jobs) is visually broken**: the 3D canvas freezes on a static splash image while the sim runs blind underneath. The game is half-playable.

## What works

- **Boot:** clean load, **zero JS errors, zero failed asset requests** across all tests.
- **Menu (v3):** renders — graffiti ASHLANE logo, red/green/gold palette, job instructions, all nav sections reachable. (`01-boot.png`)
- **Fighter select:** "WHO WALKS IN" screen with illustrated cards + POW/SPD/TGH stat bars (Bannon, Maime visible). (`14-job-pending.png`)
- **Attire select:** "WHICH LOOK" step works (MUSCLAR — Bannon).
- **Jobs:** 26 jobs listed, "CLEARED 0 / 26", locked progression (✕ on later jobs). (`12-story.png`)
- **Roam mode ("Walk the ward"):** full 3D street renders, fighters visible, movement + attacks work, objective text, banner ("VESPER CHO · ODD ANGLES"). Pixel-diff confirmed 152,809 pixels changing during play. **This is the proof the renderer works.** (`11b-roam-moved.png`)
- **Pause menu:** opens correctly with options (crowd switch, block switch, build toggles).
- **Touch controls:** Use/Jump/Grab/Hit/Spin + joystick all present at tappable sizes.
- **HUD:** HP/KI bars, H/C/L stats, FLOW combo counter increments on hits.
- **Audio plumbing:** WebAudio available (couldn't verify audible output headless).

## What's broken

### 1. CRITICAL — Bout modes render a frozen splash image (Exhibition + Story jobs)
Starting Exhibition or any story job shows a **static explosion/cityscape image** in the 3D canvas. Pixel-diff across movement + attacks: **0 pixels changed**. No fighters, no arena, no animation — ever, even after 15+ seconds. (`18-job-live.png`)

The sim underneath is alive: keyboard inputs register, FLOW counter hit 25, HP/HUD update. But the player sees nothing move. **The game cannot be played as a fighter right now.**

Roam mode renders fine on the same renderer, so this is **bout-mode specific** — likely the ring/arena stage setup used by `startBout("exhibit")` and job bouts, not the 3D pipeline itself. All fighter GLBs, props, and textures load successfully (verified in network log), so it's not an asset failure.

### 2. No service worker — not installable
`manifest.webmanifest` exists but **no service worker is registered**. Fails the installability check the owner asked for.

### 3. Stale player-visible text (known, other branches)
- Live build still says **"EXHIBITION"** (identity-audit rename to "Throw down" is on `round6/generative-art`, not deployed).
- Tagline still **"WIZARDS OF THE STREET"** — owner ordered it back to **"CONCRETE JUNGLE"** (menu v4 in progress).

## Ugly / placeholder (non-blocking)

- Menu v3 is a flat improvement but still reads generic-mobile per owner's note — menu v4 (AAA pass: character cutouts, denser art) is the fix in flight.
- Fighter-select portraits are illustrated 2D cards, not renders of the actual GLB roster.
- Webfont loading is slow (screenshot harness timed out waiting for fonts); fallback fonts render instead on slow connections.
- Keyboard-only playtest: WASD/J/K/L/Space all registered. No gamepad tested.

## Test environment notes

- Sandbox egress requires an authenticated MITM proxy; Chromium was driven through a local forward proxy (`127.0.0.1:18923`) with `ignoreHTTPSErrors`. Page-text fetch tools can't run the game — this needed a real browser.
- Screenshots via CDP `Page.captureScreenshot` (Playwright's screenshot waits forever on pending webfonts).

## Recommended fix order

1. **Bout-mode rendering** — make Exhibition/Story fights render the 3D scene like roam does. Nothing else matters until fights are visible.
2. **Service worker** — register it; make the game installable.
3. Deploy the identity-audit text + menu v4 when ready.
